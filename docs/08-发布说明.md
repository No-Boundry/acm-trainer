## 2. 功能清单
- 🗺️ **技能树 54 节点 + 5 个国内比赛赛道**（v1.10）：知识图谱由 44 扩至 **54 节点**（仍 7 层 L0–L6，新增容器与 STL 应用 / 大模拟 / 暴力与剪枝 / 表达式与括号 / 交互题 / 博弈论 / 概率与期望 / 矩阵与线性代数 / 折半搜索 / 字符串哈希）；赛道切换条（**蓝桥杯 / 天梯赛 GPLT / ICPC·CCPC 区域赛 / NOIP·CSP-S / 牛客多校**）含赛制说明、推荐难度区间、**必达进度条**（达标线 = 基本掌握及以上）、「建议优先」列表、「📚 按赛道去题库练习」与「只显示赛道节点」；节点卡片按「必达（双线框）/ 重点（内阴影）/ 非赛道（压暗）」区分
- 📋 **题单**（v1.10）：**三种建法** —— ① 题库页勾选（首列复选框 + 勾选本页全部 + 「已勾选 N 题 → 加入题单」）；② **粘贴题号文本识别**（`1741A` / `CF 1741 A` / `P3374` / `洛谷 P1000` / `LC1` / `LC 146` + CF·洛谷·力扣题面链接，自动去重匹配、力扣按 slug 反查、**未命中题号回显 ≤50 条**）；③ **按知识点 + 难度一键生成**（可套用赛道 focus，抽题按**难度分层轮转**避免挤在同一难度）；题单页含条目表格（勾选完成 / 复习状态 / 备注 / 题面 / 移除）
- 🗓️ **训练计划**（v1.10，日历排期式）：从今天起每个可用日排 `dailyTarget` 题，跳过「每周休息日」与「没空日」；给定目标日期则排到该日期为止，**超出部分计入 overflow 并明确提示**（不硬塞、不静默丢题）；日历视图按日期分组、任务可**打卡**可看题面；**标记「这天没空」并填原因后其后未完成任务自动顺延**（总题量不变、已完成不动）；支持「重新排期」与删除
- 🔁 **题单内间隔复习**（v1.10）：阶梯 **1/3/7/14/30/60 天**（6 档封顶）；**勾选完成即自动进入第 1 档**；「今日复习」跨题单汇总（`到期日 ≤ 今天`，**逾期也算**）并给出反馈：**困难退一档 / 一般进一档 / 轻松跳一档**；重复勾选不清空排期、取消勾选只清完成状态
- 📚 **题库（三数据源）**：Codeforces 全部题目 + **洛谷 P 题库（约 1.6 万道）** + **力扣算法题（3930 道）**；数据源切换（全部/Codeforces/洛谷/力扣）；洛谷难度评级（0–7）与力扣难度（简单/中等/困难）、中文标签筛选（三源合计 **31,585** 题）；**排序规则（v1.9.1）**：按难度按各题源自己的难度列（CF rating / 洛谷难度 0–7 / 力扣 简单·中等·困难）、按题号数字序（洛谷 `P10000` 在 `P1001` 之后）、空难度恒排最后、全部视图按题源分组
- 📊 **难度分布统计**（v1.9）：统计页「难度分布（按题源）」—— CF 按 rating 200 一档、洛谷按难度 0–7、力扣按简单/中等/困难，展示已练题目 / 已 AC 双系列与 AC 率、占比、合计
- 📝 **练习记录**：记录结果/耗时/备注/错题标记（CF、洛谷与力扣题均支持）；统计页 ECharts 图表（日/周趋势、知识点分布，多源标签聚合）
- 📓 **笔记/错题本**：Markdown 编辑（代码高亮）+ 自动保存；错题独立 Tab（可取消标记/删除）
- 🧩 **模板库**：算法模板分类管理、一键复制
- ⚔️ **虚拟比赛**：按难度/知识点组卷（分桶均匀抽取）、限时训练、ACM 计分（20min 罚时）、结果回看
- 🏅 **水平评估**：0.7×练习分 + 0.3×比赛分 → 近似 CF Rating 与称号，历史趋势图；**洛谷练习水平**与**力扣练习水平**（v1.9）独立计算、均不并入综合分
- ⚙️ **设置**：同步提醒/默认比赛时长/自动保存间隔；**数据导出/导入**（JSON 全量备份）；洛谷难度映射与**力扣难度映射**（v1.9，默认 1000/1500/2000）
- 📘 **STL 速查**（v1.8.2）：34 条竞赛常用 STL 资料（6 大类），含签名/复杂度/可复制代码/常见坑与 cppreference 链接，支持搜索与分类过滤

### 9c. 桌面反馈修复：学习路径荐题单一题源（v1.8）
- **现象**：学习路径节点详情「推荐练习」只出现单一题源的题目（如贪心只出 CF 题、树状数组只出洛谷题）；
- **根因**：荐题仅取节点首个标签 + problems:list 标签为 AND 语义 → CF 英文 tag 只命中 CF、洛谷中文 tag 只命中洛谷；
- **修复**：按 CF_TAGS 将节点标签拆分为 CF/洛谷两侧，双路并行抓取（未练习优先、不足补全量）后轮转合并展示，行首加 CF/洛谷题源徽标；洛谷按题号数字序、CF 按 rating 升序；组件测试锁定双路载荷与合并顺序。


### 9d. 桌面反馈修复：知识点内练习无法计入统计（v1.8 续）
- **现象**：学习路径推荐题只有「题面」入口，知识点内完成的练习无从记录 → 无法参与统计与掌握度；
- **修复**：荐题每行新增「记录」按钮，展开行内表单（结果 AC/WA/…、耗时、备注、错题标记），与题库抽屉共用 records:create 通道；提交后静默刷新技能报告与推荐列表（该题离开「未练习」队列，掌握度/推荐下一步即时更新）。

### 13.1 缺陷修复：题库「按难度」「按题号」排序异常（用户反馈，FR-25）
**三个叠加根因**：
1. **「按难度」在洛谷/力扣视图完全无效**：原实现统一用 `p.rating` 排序，但洛谷/力扣行的 `rating` **恒为 NULL** —— 它们的难度存在 `difficulty` 列
   （洛谷 0–7、力扣 1–3），因此这两个视图里所有行的排序键全等，表现为**点了没反应**；
2. **「按题号」不是数字序**：「全部」视图里洛谷行按 `p.id` 文本排序 → `P10000` 排在 `P1001` **之前**（字符串序错误）；
   力扣非数字题号（`LCR 001` / `面试题 xx` / `cnHoX6`）被 `CAST` 成 0，与数字题号混在一起；
3. **空难度位置会翻转**：降序时空值标记 `p.rating IS NULL` 也跟着 `DESC` → 未标难度/未定级的题跑到列表**最前**。

**修复（`src/main/db/repositories/problems.ts` 新增并导出纯函数 `buildOrderSql(filter)`，生成完整 ORDER BY 子句）**：
- **难度键按题源取列**：CF = `rating`，洛谷 = `difficulty`，力扣 = `difficulty`；未标难度/未定级（NULL）**恒排最后**，升序降序都不翻到最前

  3. 新增 `watch([activeTrackId, onlyTrackNodes])` → `nextTick` 后重新测量：`display:none` 会使同层卡片重排，必须重测坐标，否则留下的是「旧坐标的线」。

## 20. v1.14.1 变更（首页与启动性能：推荐题全量扫描从 12.5 秒降到 33 毫秒）

### 20.1 问题现象
用户反馈两件事：**「首页跳转题库有明显卡顿」**、**「启动速度明显变慢」**。两者其实是同一个原因 ——
v1.14.0 新增的首页推荐习题需要「题库全集」，而取全集的实现极慢，且它是**同步 **SQL，跑在主进程上，
会把整个应用（含所有 IPC 与页面跳转）一起堵住；用户点导航时正好被堵，就表现为「卡顿」。

### 20.2 根因定位（真实库实测）
用 better-sqlite3 只读打开真实库（**31764 道题 / 94 条提交记录 / 113664 条题目标签关联 / 574 个标签**）逐项计时：

| 取数方式 | 耗时 |
| --- | --- |
| 原实现：`list()` 分页翻全量（每页 200，共 159 页），每行带 3 个相关子查询（标签聚合 / `EXISTS` 已练习 / 最近状态） | **9072 ms** |
| 精简列全量单条 SQL（id / 名称 / 题源 / 难度 / 通过数 / 标签串） | **83 ms** |

即 **109 倍差距**，而 `recommend-service.allProblems()` 恰恰用的是前者，所以首页每次进入都要等 9 秒以上
（GUI 实测 `recommend:get` IPC **12498 ms**，首页统计卡片 **13984 ms** 才可见）。

顺带查出**第二个真实缺陷**：`RecordsRepo.list()` 的 `pageSize` 上限是 200，而掌握度、水平评估、
首页推荐、组卷四处都写 `list({ pageSize: 100000 })` 想取全量，**被静默截断成前 200 条**：

- `services/skill.ts` → 掌握度少算记录；
- `services/rating.ts` → 水平评估少算记录；
- `services/recommend-service.ts` → 已练习段漏题；
- `services/contest.ts` → 组卷**只在题库前 200 道题里抽题**。

### 20.3 修复内容
1. **`ProblemsRepo.leanAll()`**：单条精简 SQL 取全库（不带相关子查询、不算已练习/最近状态），
   实测 **171 ms**（含 3.17 万行映射）；配套 `ProblemsRepo.candidates(filter, max)` 供组卷取候选，
   `buildWhere()` 抽成私有方法供 `list()` 与 `candidates()` 共用。
2. **`RecordsRepo.all()` / `count()`**：真正的不分页读取，四处调用点全部改用它，
   修掉「组卷只能在前 200 题里抽」等静默截断。
3. **三级缓存**（`services/recommend-service.ts`）：
   - 题库缓存 `leanCache`：键 = 题数 + 三个题源的最后同步时间，5 分钟 TTL；
   - 标签统计缓存 `tagUsageCache`：键 = 题库键 + 记录数 + 标签集；
   - **推荐结果缓存 `resultCache`**：键 = 题库键 + 记录数 + 稳定序列化后的参数（`filterTags`/`knowledgeIds`
     排序后参与），命中即返回，避免对 3.17 万题重复做筛选排序；「随机换一批」因每次结果不同不缓存。
   数据一变（同步、新增提交、改设置）键就变，无需手动失效。
4. **首页首帧优先**：`DashboardPage` 把推荐与标签的加载推迟到 `requestAnimationFrame` + `setTimeout` 之后，
   先让统计卡片出画面，避免首屏空白。
5. **`verify:perf`**：新增 `tools/gui-perf.cjs`（`npm run verify:perf`），把真实库**副本**复制到临时目录后启动应用，
   测量启动、页面切换与关键 IPC 耗时 —— 既能自查性能，又不会写坏用户的库。

### 20.4 优化前后对比（真实库副本，同一台机器，GUI 端到端）
下表为两次实跑中较好的一次（同机复跑有 ±10% 波动），可用 `npm run verify:perf` 自行复现：

| --- | --- | --- | --- |

## 21. v1.15.0 变更（首页推荐去重 + STL 速查补齐初始化 / 清空 / 释放内存）

### 21.1 问题现象
两个用户反馈：

1. **首页「推荐习题 → 未练习」栏 8 条全是同一道题** —— 题名全叫 "Treasure Hunt"，题号是连号的 `1639:A`…`1639:H`，
   看上去像同一行复制了 8 次，推荐区等于失效；
2. **STL 速查「功能不全」** —— 反馈原话：「STL速查中的函数部分功能不全，如清空，初始化等操作」：
   条目里能查到 `push_back` / `insert` 这类接口签名，但**查不到怎么初始化**、**怎么清空**、**怎么释放内存**。

现象①的复现：真实库（31764 题）进入首页即可看到，8 条题名完全一致、题号连续；截图为 `.gui-verify/15-dashboard-recommend.png` 的旧版。
现象②的复现：进入「STL 速查」搜 `clear`，只能搜到零星的 `erase` / `clear` 提及，`vector` 条目里没有「填充构造 / 初始化列表 / 清空 / 释放」的成组示例。

### 21.2 根因与实测数据（现象①）

只读打开真实库统计，问题链条非常清楚：

| 实测项 | 数字 |
| ---- | ---- |
| 题库总题数 | **31764** |
| `solved_count = 0` 的题 | **132** 道（Codeforces **30** = 实验场/gym；洛谷 **102**） |
| 其中 `rating` 同时为 NULL | **117** 道 |
| 这 132 道题分布在几场比赛 | **8** 场 |
| `contest_id = 1639` 的题 | **11** 道，题名去重后 **1** 个（A–K 全叫「Treasure Hunt」） |

三层原因叠加：

1. **0 被当成排序值**：未练习排序 `byAc` 按 `solvedCount` **升序**，而 `solved_count = 0` 的真实语义是「**从未采集到 AC 数**」，
   数值上却是最小值 → 这 132 道题集体抢到最前；
2. **`rating` 破平局失效**：`ratingOf()` 对 `rating = null` 返回 `Number.MAX_SAFE_INTEGER`，CF 1639 这 11 道题**全是同一个值**，比较恒为 0；
3. **`id` 破平局连号**：`1639:A` < `1639:B` < … < `1639:K`，11 条同名题紧挨着，`slice(0, 8)` 取前 8 条 → 同一个题名出现 8 次。

### 21.3 两项修复
**（1）`acOf()`：0 值不再当排序键**（`src/main/services/recommend.ts`）

```ts
const acOf = (p: ProblemRow): number =>
  p.solvedCount > 0 ? p.solvedCount : Number.MAX_SAFE_INTEGER
```

未练习排序改用 `acOf(a.p) - acOf(b.p) || ratingOf(...) || id.localeCompare(...)`：0 = 未采集 → 视为未知值，**排到最后**。

**（2）`diversify()`：推荐位多样性截断（新增导出）**

```ts
export function diversify(items, limit, perContest = 2): RecommendedProblem[] {
  // 按「来源+比赛」≤ perContest 条、按「来源+题名」≤ 1 条
  // 超额的按原顺序进 overflow（不丢弃），最后 [...picked, ...overflow].slice(0, limit)
}
```

- 同一场比赛**最多 2 条**、同一题名**最多 1 条**；
- 超出的条目**按原顺序追加到后面**（不丢弃）→ `limit` 大于可用多样性时**回填**，不会少给条目；
- 未练习段改为 `diversify(freshSorted, freshLimit)`；**用户所选排序方式（`recommendOrderFresh`）语义不变**，已练习段不动。

效果：未练习栏 8 条**题名互不相同**，同一场比赛最多 2 条；0 AC 题仍在池子里，但不再霸占前排。

### 21.4 STL 速查扩充清单（现象②）
`src/shared/stl-reference.ts` **34 → 35 条**，分类仍是 **6** 个（序列容器 4 / 容器适配器 3 / 关联容器 3 / 其他常用 4 / 算法库 10 / 技巧与坑 11）。

为下面 **12 个容器条目**统一补齐四类写法（**① 初始化 ② 增删改查 ③ 清空 ④ 释放内存 / swap**）：

| 容器 | 初始化 | 清空 | 释放内存 |
| ---- | ---- | ---- | ---- |
| `vector` / `deque` | `vector<int> v(n, 0)`、`{1,2,3}`、迭代器区间 | `v.clear()` | `vector<int>().swap(v)`、`v.shrink_to_fit()` |
| `array<T,N>` | `array<int,3> a{}`、`a.fill(0)`（聚合初始化） | **没有 `clear()`** → `a.fill(0)` 或 `a = {}` | 定长、无堆分配，无需释放 |
| `string` | `string s(n, 'x')`、`s = "abc"`、`string(begin, end)` | `s.clear()` 或 `s = ""` | `string().swap(s)` |
| `stack` / `queue` / `priority_queue` | `stack<int> s;`、`queue<int> q;`、`priority_queue<int, vector<int>, greater<int>> pq;` | **没有 `clear()`** → `s = {}` 或 `stack<int>().swap(s)` | 后者同时释放底层容器内存 |
| `set` / `map` / `unordered_*` | `set<int> st{1,2,3}`、`map<string,int> m{{"a",1}}` | `st.clear()`、按 key `m.erase(k)` | `Container().swap(x)`（节点逐个释放） |
| `pair` / `tuple` | `pair<int,int> p{1,2}`、`tuple` + `make_tuple` / `tie` | 重新赋值即可（无 `clear()`） | 栈对象，无需释放 |
| `bitset<N>` | `bitset<8> b(string("1010"))`、`b.set()` | **没有 `clear()`** → `b.reset()` / `b.reset(i)` | 定长位图，无需释放 |

**新增条目「初始化与清空速查对照」**（id `stl-init-clear`，分类「其他常用」）：一页看完所有容器的初始化写法、清空方式对照表、
内存释放方式，以及 **4 个常见坑**：① 多测忘清空（全局容器跨 case 残留）；② 邻接表要**逐行** `g[i].clear()`；
③ `clear()` **不缩容**（内存峰值仍在）；④ `getline` 前残留换行（`cin >> n` 后要先吃 `\n`）。

适配器与 `array` / `bitset` **没有 `clear()`** 这件事在条目里**逐条标注**，避免照抄 `s.clear()` 编译报错。

### 21.5 文档生成缺陷修正
