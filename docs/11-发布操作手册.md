# 11 发布操作手册（ACM-Trainer）

本手册是「从改完代码到用户在 GitHub 上看到安装包」的完整可执行清单。
每一步都标注了**为什么**做以及**历史上踩过的坑**，照着做即可，不需要重新摸索。

- 适用版本：v1.20.0 起（更早版本的细节差异见 `docs/08-发布说明.md`）
- 环境：Windows 10/11 + PowerShell 5.1（本机**没有 pwsh 7**）+ Node 22
- 仓库：<https://github.com/No-Boundry/acm-trainer>（作者账号 `No-Boundry`）

## 1. 发版前的准备

### 1.1 确定版本号

| 版本位 | 什么时候动 |
| --- | --- |
| patch（x.y.**z**） | 纯缺陷修复、性能修复，无新功能 |
| minor（x.**y**.0） | 有新功能 / 新界面 / 新数据结构（本项目绝大多数） |
| major | 不兼容变更（回退过 v2.0 本地判题，就是这个级别） |

改 `package.json` 的 `"version"` 字段：**必须用编辑器（write/edit 工具）改，绝对不要用 PowerShell 的 `Get-Content | Set-Content`**。
PowerShell 5.1 按 ANSI 回写会破坏中文 `description`，随后 `npm` 直接报：

```
npm error EJSONPARSE ... Bad control character in string literal in JSON at position 109
```

真发生了就只能 `git checkout -- package.json` 重来。

### 1.2 代码侧检查

- 新增的 IPC 通道都登记在 `src/shared/channels.ts`（preload 白名单从 `INVOCATION_CHANNELS` 自动生成，不需要手改）。
- 新增的数据库表加进 `src/main/db/schema.ts` 的 `SCHEMA_SQL`（幂等 `CREATE TABLE IF NOT EXISTS`，老库自动补），并同步 `src/main/services/data.ts` 的 `TABLES`（备份/恢复要带上）。
- 有旧数据迁移的，写幂等迁移函数挂到 `src/main/db/index.ts` 的 `migrate()` 里（参考 `migrateProblemTagsToCanonical`）。
- 渲染层传给主进程的数据必须是**纯对象/数组**：Vue 的响应式 Proxy 过 IPC 会报
  `An object could not be cloned.`（`[...arr]` / `{...obj}` 拆一层即可）。

### 1.3 文档与截图

- `docs/08-发布说明.md`：新增一节 `## N. vX.Y.Z 变更`，写清「改前现象 → 根因 → 修法 → 验证数字」。
- `docs/00/01/03/04/05/06/07/09` + `README.md`：新增的 FR 条目、设计说明、测试统计、验收清单、手册 FAQ、README 徽章。
- 截图从 `.gui-verify/` 或 `.gui-smoke/` 复制到 `docs/images/`，**用 1.19.0 之后的新构建重拍**（侧边栏会显示版本号，旧图会露馅）。
- 中文文档改完做一次自检（U+FFFD 与 BOM 必须为 0）：

```js
// .tmp-doccheck.cjs
const fs = require('fs')
for (const f of process.argv.slice(2)) {
  const s = fs.readFileSync(f, 'utf8')
  const bad = (s.match(/\uFFFD/g) || []).length
  const bom = s.charCodeAt(0) === 0xfeff
  console.log(`${f}: U+FFFD=${bad} BOM=${bom}`)
}
```

## 2. 全量自检（必须在打包之前）

```powershell
$env:NODE_EXTRA_CA_CERTS=$null
node node_modules/vitest/vitest.mjs run *>&1 | Out-File -Encoding utf8 .tmp-full.log
Select-String -Path .tmp-full.log -Pattern "Test Files|Tests  |FAIL"
```

- 期望：`Test Files ... passed`、`Tests  ... passed`、无 `FAIL`。
- 单元 / 集成 / 渲染层测试都在 `tests/` 下，跑一次约 20–40 秒。

类型检查（两条都必须 0 输出）：

```powershell
node node_modules/typescript/bin/tsc --noEmit -p tsconfig.node.json  *>&1 | Out-File .tmp-tsc.log
node node_modules/vue-tsc/bin/vue-tsc.js --noEmit -p tsconfig.web.json *>&1 | Out-File .tmp-vtsc.log
(Get-Item .tmp-tsc.log).Length; (Get-Item .tmp-vtsc.log).Length   # 都应为 0
```

> **为什么不能用 `npm.cmd run typecheck`**：它内部串联两个 npm 脚本，Windows 下输出会被管道吞掉，
> 看不到是哪个文件报错。直接调 `node node_modules/...` 最稳。

## 3. 构建与 GUI 验收

```powershell
npm.cmd run build          # 产物在 out/，GUI 脚本依赖它
npm.cmd run verify:gui     # 端到端走查（100+ 项）
npm.cmd run verify:smoke   # 关键路径冒烟（30+ 项）
```

- `verify:gui` 会真的启动 Electron（Playwright `_electron.launch`），每项检查输出 `PASS — 说明 :: 实测值`，
  末尾打印 `SUMMARY: n/n 检查通过`。
- **改了源码不 build 就跑 GUI = 测旧包**，这是历史上最常犯的错。
- 两个脚本都靠 `ACM_USER_DATA` 起干净的用户数据目录，不会污染真实库。
- 脚本内部若要点「题面」，注意它会真的用 Edge 打开浏览器窗口（`openInEdge`）——
  发版走查时尽量用种子数据 + `window.api.invoke` 直调，避免弹窗打断。

其它可选门禁：

```powershell
npm.cmd run verify:perf    # 首页/推荐/题库的性能采样（用真实库副本，见 tools/gui-perf.cjs）
npm.cmd run verify:lc      # 力扣在线同步（需要网络，约 40 秒）
```

## 4. 打包与安装包自检

```powershell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
npm.cmd run build:win
```

- 不加镜像环境变量时 electron-builder 会去 GitHub 下 Electron 二进制，本机网络经常
  `ETIMEDOUT` / `Connection was reset`，表现为卡在 `downloading electron`。
- 产物：`dist\ACM-Trainer-<version>-setup.exe`（约 90MB）与 `dist\win-unpacked\`。
- 打包后清理（`dist/` 只保留当前版本）：

```powershell
Get-ChildItem dist\*.exe | Where-Object { $_.Name -notlike "*1.20.0*" } | Remove-Item -Force
Remove-Item dist\builder-debug.yml, dist\latest.yml -ErrorAction SilentlyContinue
```

### 4.1 `npm run verify:asar`

```powershell
npm.cmd run verify:asar
# 或显式指定： npm.cmd run verify:asar -- 1.20.0
```

它会做四件事（全部 PASS 才算发版合格）：

1. 安装包存在并打印体积；
2. 解出 `dist\win-unpacked\resources\app.asar`，比对 asar 内 `package.json` 的版本号；
3. 把 asar 解到临时目录，与 `out\` **逐文件 sha256** 比对（`out\` 里每个文件都必须在 asar 里且内容一致）；
4. 抽查本次新功能的关键串是否真的进了包。

> **坑**：`@electron/asar` 的 `extractFile(asar, '\\out\\main\\index.js')` 对本项目 asar 会报
> `"…" was not found in this archive`，即使 `listPackage()` 里明明有。所以脚本统一用 `extractAll()`。
>
> **为什么非要比 sha256**：历史上出现过「改了源码没重新 build 就打包」和「删了死代码仍沿用旧 asar」，
> 只看文件存在会漏掉这两种致命问题。版本号对不上时，安装包里的 `app.asar` 就是错的。

发版前把 `tools/asar-check.cjs` 里的 `NEEDLES` 更新成本次新增的界面文案 / 通道名 / 函数名。

## 5. 推送与 GitHub Release

### 5.1 推送代码

```powershell
# 提交信息写在文件里再 commit -F，避免中文经 shell 变乱码
# （.tmp-commit-msg.txt 已被 .gitignore 的 .tmp-* 忽略）
git add -A
git commit -F .tmp-commit-msg.txt
Remove-Item .tmp-commit-msg.txt
git push origin main
```

- 本机到 `github.com:443` 经常 `Recv failure: Connection was reset` / `Failed to connect ... after 21000 ms`，
  **多试几次**即可（历史上有 9 次全失败、次日一次成功的情况）。
- PowerShell 会把 git 的 stderr 当成 `NativeCommandError` 并给出 `exit code 1`，**即使推送成功**。
  判断依据只看输出里有没有 `main -> main` 或 `Everything up-to-date`。

### 5.2 发布 Release（需要 PAT）

PAT 由用户提供，放在 `C:\Workspace\gh-token.txt`（单行、`ghp_` 或 `github_pat_` 前缀、不要带引号或空格）。
用完**立即删除该文件**。

经典 token 需要的勾选：`repo`（私有仓库全套）或 `public_repo`（公开仓库足够，本项目用这个就够）。
Fine-grained token：`Contents: Read and write`（建 tag、发 release、传附件都靠它）。

发布流程在 `C:\Workspace\acm-trainer\.tmp-release.ps1`（被 `.gitignore` 忽略，长期保留可复用）：

1. `GET https://api.github.com/user` 校验身份；
2. `POST /repos/{owner}/{repo}/git/refs` 建 `refs/tags/vX.Y.Z`（已存在则跳过）；
3. `POST /repos/{owner}/{repo}/releases` 建 **draft**；
4. 用 .NET `HttpClient` + `StreamContent` 把 `dist\ACM-Trainer-X.Y.Z-setup.exe` 传到
   `https://uploads.github.com/repos/{owner}/{repo}/releases/{id}/assets?name=<文件名>`；
5. `PATCH /repos/{owner}/{repo}/releases/{id}` 把 `draft` 置 `false` 发布。

执行方式（绕过 PowerShell 执行策略）：

```powershell
$env:NODE_EXTRA_CA_CERTS=$null
Invoke-Expression ([System.IO.File]::ReadAllText('C:\Workspace\acm-trainer\.tmp-release.ps1', [System.Text.Encoding]::UTF8))
```

> **坑 1（最致命）**：不要用 `Invoke-RestMethod -Body ([Text.Encoding]::UTF8.GetBytes($json))`。
> PS 5.1 会把 `byte[]` 再序列化成 `[123,34,...]` 当 JSON 发出去，GitHub 返回
> `422 Invalid request. For 'links/0/schema', 123 is not an object.`，而且抛出的异常对象巨大，
> 把真正的错误埋掉。**必须**用：
>
> ```powershell
> $body = New-Object System.Net.Http.StringContent($json, [System.Text.Encoding]::UTF8, 'application/json')
> ```
>
> **坑 2**：`[System.Net.Http.HttpMethod]::Patch` 在 .NET Framework 里不存在，`New-Object` 会报
> 「值不能为 null。参数名: method」。**必须**用 `New-Object System.Net.Http.HttpMethod('PATCH')`。
>
> **坑 3**：`uploads.github.com` 与 `api.github.com` 通常可用，而 `github.com:443` 常常不通——
> 所以「网页打不开」不代表发不了 Release，脚本走的是 API 域名。

### 5.3 发布后校验

```powershell
$url = (Invoke-RestMethod -Headers @{Authorization="Bearer $tok";'User-Agent'='acm-trainer'} `
  "https://api.github.com/repos/No-Boundry/acm-trainer/releases/tags/vX.Y.Z").assets[0].browser_download_url
# Range 请求应返回 206，且首字节为 MZ（0x4D）
```

- 附件大小应与本地 `dist\*.exe` 一致（约 89.8MB）；
- 发布说明里不允许出现 `U+FFFD`（本地 `.tmp-release-body.md` 先自检一遍再上传）；
- 确认 `draft: false`、`prerelease: false`。

### 5.4 发布后收尾

- 删除 `C:\Workspace\gh-token.txt`（**必做**）；
- 删除 `.tmp-*.ps1` / `.tmp-*.cjs` / `.tmp-*.log` 等临时文件；
- `git status --short` 应为空，`git status -sb` 应显示 `main...origin/main`（无 `ahead`）。

## 6. 回滚

| 场景 | 做法 |
| --- | --- |
| 只回退功能代码 | `git revert <commit>`，重新走 §2–§4 |
| 数据库迁移出问题 | 迁移函数都是幂等的；先把 `%APPDATA%\acm-trainer\acm-trainer.db` 备份，再回退构建 |
| 安装包本身有问题 | 从上一个 Release 重新下载安装包覆盖安装；用户数据在 `%APPDATA%\acm-trainer\`，**不要删** |
| Release 发错了 | 先 `PATCH` 回 `draft: true` 隐藏，修好后重新发；直接删 Release 会让已下载用户拿到 404 |

## 7. 常见问题（发版专属）

| 现象 | 原因 / 解法 |
| --- | --- |
| `npm error EJSONPARSE ... position 109` | PowerShell 回写 `package.json` 破坏中文，`git checkout -- package.json` 重来，改用编辑器 |
| 打包卡在 `downloading electron` | 没设 `ELECTRON_MIRROR` / `ELECTRON_BUILDER_BINARIES_MIRROR` |
| GUI 验收全红但代码没问题 | 忘了 `npm.cmd run build`，脚本测的是旧 `out/` |
| `Process failed to launch!` | 启动 Electron 时继承了 `ELECTRON_RUN_AS_NODE`，工具脚本里要 `delete env.ELECTRON_RUN_AS_NODE` |
| `Cannot find module 'better-sqlite3'` | 该模块是原生模块，`npm.cmd rebuild` 或直接用 `dist\win-unpacked` 里的版本验证 |
| 中文文件出现 `锟斤拷` / `鍏ㄨ` | 用了 `Set-Content -Encoding utf8` 或 `Out-File` 覆盖源码；源码要恢复，输出日志用 `Out-File` 可以，但**不要回写源码** |
| `node -e "..."` 报 `ParserError` | 内联脚本里的中文/引号被 cmd 截断；改成写 `.tmp-xxx.cjs` 再 `node .tmp-xxx.cjs` |
| `npm.ps1 / npx.ps1 无法加载，因为在此系统上禁止运行脚本` | 用 `npm.cmd` / `npx.cmd`；自定义 `.ps1` 用 `Invoke-Expression ([IO.File]::ReadAllText(...))` 执行 |
