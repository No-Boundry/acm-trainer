# 00 项目概述（ACM-Trainer）

## 1. 项目名称
**ACM-Trainer（ACM 训练助手）** —— 面向个人 ACM/ICPC 学习与训练的本地桌面应用。

## 2. 项目背景与目标
- 用户为计算机专业大二学生，正在进行 ACM/ICPC 竞赛的学习与训练。
- 痛点：题库分散、练习记录难以统计、错题与题解笔记零散、缺少针对性的水平反馈。
- 目标：提供一个**本机自用、单人使用**的一站式训练管理工具，覆盖：
  - 刷题（**三大题库**：Codeforces、洛谷 P 题、力扣 LeetCode 算法题，合计 3 万余题）
  - 练习记录、统计与**难度分布分析**
  - **技能树与学习路径**（54 个知识点，7 层；**5 个国内比赛赛道**：蓝桥杯 / 天梯赛 / ICPC·CCPC / NOIP·CSP-S / 牛客多校）
  - **题单**（题库勾选 / 粘贴题号识别 / 按知识点+难度生成）与**训练计划**（日历排期、没空日顺延、打卡）
  - **题单内间隔复习**（1/3/7/14/30/60 天阶梯 + 今日复习反馈）
  - **首页推荐习题**（已练习按遗忘曲线排序 / 未练习优先「练习中」知识点）与**已练习标签**展示
  - 错题本与题解笔记
  - 算法代码模板库
  - 虚拟比赛/限时训练
  - 参赛水平评估（折算近似 CF Rating + 称号；洛谷/力扣练习水平独立展示）

## 3. 开发方式
采用 **SDD（Specification-Driven Development，规格驱动开发）**：
1. 先产出并确认规范文档（本文档体系）；
2. 依据文档中的任务分解（05）按依赖关系逐步实现；
3. 每完成一个里程碑进行验证与验收。

## 6. 运行环境约束
- 系统：Windows 10/11（目标平台）；应用为本地桌面应用。
- 网络：首次同步 Codeforces / 洛谷 / 力扣题库及查看题面**需要联网**；已同步的数据支持**离线浏览**。
- 单用户、无账号体系、数据全部保存在本机 SQLite。

## 7. 项目范围（v1.0）
### 范围内
- 题库浏览/筛选/同步（CF 数据源；v1.1 起增加洛谷、v1.9 起增加力扣）、练习记录、统计图表、错题本、Markdown 笔记、
  代码模板库、虚拟比赛、水平评估、本地设置。当前交付版本能力见 §9。

### 范围外（v1.0 不做）
- 账号系统、云同步、多用户排行榜；
- 站内代码评测（提交在 CF 页面进行，应用内手动记录结果）；
- 爬取洛谷等其他 OJ 数据（**v1.1 洛谷与 v1.9 力扣为后续版本追加，已实现**）；
- 手机端 / 多平台发布。

## 8.8 当前版本功能补充（v1.16.0：题源全局联动）
> v1.16.0 是**功能版本**，但改动同样很小：**无新增数据表、无新增 IPC 通道、无新增设置项**，只给两个已有通道各加一个 `source` 参数。

**能力补强：题源（平台）从「每页各管各的」变成「全局一个状态」。**

| 场景 | v1.15.0（改前） | v1.16.0（改后） |
| ---- | ---- | ---- |
| 题库页选「洛谷」后回首页 | 首页推荐仍是**全部平台**混合结果，「已练习标签」的题数 / 已练数也是全库口径 | 首页推荐**只出洛谷题**（标题旁标「仅 洛谷」，「已练习标签」标题追加「（仅 洛谷）」），标签计数按洛谷收窄 |
| 在首页推荐区切题源 | 首页**没有**题源入口，只能去题库页切，且切了首页也不认 | 推荐区上方一行 `[全部] [Codeforces] [洛谷] [力扣]`，切完**题库页跟着变**（同一 Pinia store 的 `filter.source`） |
| 非「全部」时的空态 | 空态只说「没有符合条件的未练习题目」，不知道是按哪个平台算的 | 空态写明「洛谷中没有符合条件的未练习题目」 |
| 请求参数 | `recommend:get` / `stats:tagUsage` 不带题源，后端无法收窄 | 两者都带 `source`；`tagUsage()` 把题源条件与标签条件 `AND` 拼在同一条 SQL；缓存键含 `source`，切源不会读到旧计数 |
| 脏值 / 非法 `source` | 无此参数 | `mergeRecommendSettings()` 归一化：只接受 `cf/luogu/leetcode`，其余退化为 `all`，避免非法值把推荐**静默清空** |
