## 2. 单元测试用例（核心）

### 2.1 水平评估（rating.ts）
| 用例 | 输入 | 期望 |
| ---- | ---- | ---- |
| 全 AC 且难度均值 1500 | 3 题全 AC，rating 1400/1500/1600 | practice=1500 |
| 正确率 50%，均值 1500 | 2 题 1AC1WA，rating 1400/1600 | practice=1500−150=1350 |
| 无有效记录 | 空输入 | practice 无效 → final 无效 |
| 无比赛数据 | 练习有效、比赛 0 场 | final = practice |
| 比赛分合成 | practice=1400, contest=1600 | final=0.7×1400+0.3×1600=1460 |
| 称号边界 | 999/1000/1199/1200/1599/1600/1899/1900/2199/2200 | 与映射表逐一对齐 |
| 下限钳制 | 全错且均值 1200 | practice=max(800, 1200−300)=900 |

### 2.2 ACM 罚时（contest.ts）
| 用例 | 输入 | 期望 |
| ---- | ---- | ---- |
| 一题：AC@30min，1 次 WA | wrongCount=1, acSeconds=1800 | penalty=1800+20×60=3000s |
| 未 AC | wrongCount=2, acSeconds=null | penalty 不计入 |
| 总罚时 | 两题如上 + 纯 AC 一题 600s | total=3000+600=3600s |

### 2.3 组卷（contest.ts）
| 用例 | 输入 | 期望 |
| ---- | ---- | ---- |
| 均匀抽取 | 候选 30 题 rating 800–2000，count=5 | 结果 5 题不重复，rating 覆盖 5 个分桶 |
| 候选不足 | 候选 3 题，count=5 | 放宽后仍不足 → 抛 VALIDATION |
| 排除已用 | excludeIds 命中 | 结果不含被排除题 |

### 2.4 筛选/分页（problems repository）
| 用例 | 输入 | 期望 |
| ---- | ---- | ---- |
| 组合筛选 | rating 1200–1600 + tag 'dp' + 未练习 | 仅返回满足全部条件的题，分页 total 正确 |
| 关键字 | keyword='1741' | 匹配 id 前缀 |
| 排序 | sortBy=rating 降序 | 首条为最大 rating |

## 4. 手动验收清单（最终验收逐项勾选）

### 4.1 题库（FR-1）
- [ ] 首次同步题库：进度条显示、完成后题目可浏览、数据量 ≥ 8000（联网时）
- [ ] 重复同步不产生重复数据，显示"新增/更新"数量
- [ ] 断网同步失败：有错误提示，本地题库仍可浏览
- [ ] 组合筛选（难度+标签+练习状态+关键字）结果正确
- [ ] 排序切换（难度/题号/AC数）正确
- [ ] 打开题面：弹出独立窗口显示 CF/洛谷题面（v1.7 FR-10）；外部链接在系统浏览器打开；关闭题面窗口不影响主窗口布局
- [ ] 启动时距上次同步 >24h 有提示

### 4.2 记录与统计（FR-2）
- [ ] 记录一次 AC（含耗时/备注）→ 题目标记"已练习"
- [ ] 记录 WA 并勾选错题 → 错题列表可见
- [ ] 记录可编辑/删除
- [ ] 统计页：总览数、日/周柱状图、知识点分布与手动核对一致

### 4.3 笔记与模板（FR-3/FR-4）
- [ ] 新建 Markdown 笔记（含代码块）→ 预览渲染正确、代码高亮
- [ ] 笔记自动保存（停顿 2s）与显式保存均生效
- [ ] 笔记关联题目，从题目详情可打开对应笔记
- [ ] 搜索（标题/内容/标签）命中正确
- [ ] 模板新建/编辑/删除、分类分组、复制到剪贴板成功

### 4.4 虚拟比赛（FR-5）
- [ ] 组卷：题数/难度/标签生效，无重复题，难度分布均匀
- [ ] 计时开始/倒计时显示；提交记录秒数正确
- [ ] 结束：solved、总罚时、每题状态/耗时/罚时与手工计算一致
- [ ] 结果页回看历史比赛

### 4.5 水平评估（FR-6）
- [ ] 有练习+比赛数据时，Rating 分解项（练习分/比赛分/正确率）显示
- [ ] 称号与颜色按映射表正确
- [ ] 重算后历史新增一条，趋势折线更新
- [ ] 免责声明可见

### 4.6 系统（FR-7、NFR）
- [ ] 设置项读写生效
- [ ] 冷启动 ≤ 5s；列表翻页/筛选 ≤ 500ms（实测计时）
- [ ] 断网状态：除同步与题面外全部功能可用
- [ ] 高分屏下界面无错位

## 15. 水平评估页回归（v1.8.4，用户反馈「界面为空」）
> 根因：`RatingRepo` 用 `SELECT *` 后取 `row.createdAt`（DB 列为 snake_case `created_at`，未取别名）→ 历史快照的
> `createdAt` 恒为 undefined；页面趋势图 computed 调 `h.createdAt.slice()` 抛错 → 首次「重新计算并记录」（或自动记录）
> 产生第一条历史后，**整个水平评估页渲染失败（空白）**。修复：SQL 显式 `created_at AS createdAt`；页面侧同时做防御
> （单条字段异常不再让整页崩）。

| 组 | 用例 | 说明 |
| -- | ---- | ---- |
| 仓库层字段映射 | insert 返回的 createdAt 为 `YYYY-MM-DD HH:MM:SS` 字符串；history 每条 createdAt 可解析且按时间升序 | tests/integration/rating-e2e.test.ts（1 例，v1.8.4 新增） |
| 页面渲染 | 无历史：分值/称号/「还没有历史记录」；有历史：页面与卡片正常、**非空白**（修复前此处整页崩）；单条 createdAt 缺失也不抛错；点「重新计算并记录」调用 `rating:recalc` | tests/renderer/rating-page.test.ts（4 例，jsdom + ChartBox 桩） |
| GUI 端到端 | 进入水平评估页渲染 hero；点「重新计算并记录」写历史后页面仍渲染且趋势图 canvas 存在（v1.8.4 修复回归锁） | tools/gui-verify.cjs（2 项断言） |

### 25.3 迁移用例的强制要求（本版新增规则）

- **任何新增的迁移函数都必须有「第二次执行返回 0 / 数据快照不变」的幂等用例**。理由：`migrate()` 在**每次启动**时执行，不是只跑一次；若迁移不幂等，用户重启几次就会把数据越改越少（v1.18 的 `dropTag` / `dropLinks` 就是最危险的形态 —— 少写一个 `target.id === row.id` 判断就会删掉自己的关联）；
- 幂等用例必须**同时断言返回值与数据快照**：只断言 `=== 0` 无法发现「返回 0 但已经改了数据」的假幂等；
- 迁移用例走**手工建库**（`new Database(':memory:')` + `SCHEMA_SQL` + 手写旧形态数据），不复用仓库初始化 —— 真实仓库初始化时 `migrate()` 已经跑过，构造不出「迁移前」的库。
- **合成库只能验逻辑，真实库必须手工跑一次留档**：v1.18 的合成分支（`merged === 2`、第二次返回 `0`）只能证明「合并与幂等成立」，**证明不了真实数据的收敛形态**。本版另用真实库（本机 31764 题）手工执行了一次 `migrateProblemTagsToCanonical()` 并记录前后数字：标签 **574 → 516**、`problem_tags` **113664 → 113577**、无题标签 **0**，第二次执行返回 **0**。这类「真实数据快照」在 `docs/03` §29.7 留档，不属于自动化用例（会依赖用户本地库）。
