# 02 概要设计 —— ACM-Trainer

- 版本：v1.0
- 输入：01 需求规格说明书
- 说明：定义系统架构、模块划分、进程通信与技术选型，是 03 详细设计的骨架。

## 1. 架构风格
采用 **Electron 三进程分层架构 + 模块化**：

```
┌──────────────────────────────────────────────────────────────┐
│                       渲染进程 Renderer                         │
│  Vue 3 SPA：页面路由 / Pinia 状态 / 组件 / ECharts / markdown  │
│          └──────────────┬──────────────────┘                  │
│   api/（IPC 封装，仅通过 preload 暴露的桥接对象调用）            │
├─────────────────────────┼────────────────────────────────────┤
│                       预加载 Preload                           │
│      contextBridge.exposeInMainWorld('api', ...)              │
│      contextIsolation: true, nodeIntegration: false           │
├─────────────────────────┼────────────────────────────────────┤
│                       主进程 Main                              │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌────────────────────┐  │
│  │  db/    │ │services/│ │  ipc/   │ │ window & statement │  │
│  │ repository│  cf      │ │ 通道注册 │ │ 主窗口 / WebContents│  │
│  │ schema   │  rating   │ │         │ │ View 题面管理       │  │
│  │          │  contest  │ │         │ └────────────────────┘  │
│  └────┬────┘ └────┬────┘ └────┬────┘                         │
│       └───────────┴───────────┴────► better-sqlite3 (.db)    │
└──────────────────────────────────────────────────────────────┘
                  ▼ 外部依赖：Codeforces REST API（仅主进程访问）
```

**分层职责**：
- **Main（主进程）**：唯一持有 Node/DB/网络权限；业务逻辑（数据访问、CF 同步、算法、比赛计时）。
- **Preload**：以白名单方式暴露 `window.api`（每个方法 = 一个 IPC invoke 通道），渲染进程无 Node 能力。
- **Renderer（渲染进程）**：纯 UI 与交互，通过 `window.api` 调用主进程能力；状态管理用 Pinia。

## 2. 模块划分

### 2.1 主进程模块（src/main/）
| 模块 | 文件 | 职责 |
| ---- | ---- | ---- |
| 入口 | `index.ts` | 创建主窗口、注册 IPC、初始化数据库、启动服务 |
| 数据库 | `db/schema.ts` | SQLite 建表语句与迁移 |
| 数据访问 | `db/repositories/*.ts` | 每个业务实体一个 repository：problems/tags/records/notes/templates/contests/settings |
| CF 服务 | `services/cf.ts` | 调用 CF API、解析、入库、同步进度回调 |
| 水平评估 | `services/rating.ts` | 纯函数：练习分、比赛分、综合 Rating、称号映射、历史写入 |
| 比赛服务 | `services/contest.ts` | 组卷、计时、提交落库、ACM 罚时计算（纯函数 `computePenalty`） |
| 题面窗口 | `services/statement.ts` | v1.7 起独立 BrowserWindow（创建/切换/关闭 + 白名单护栏）；原 WebContentsView 内嵌（v1.0–1.6）已废弃 |
| IPC 注册 | `ipc/*.ts` | 按域注册 handler，统一错误响应 |

### 2.2 共享层（src/shared/）
- `types.ts`：跨进程共享的 TypeScript 类型（Problem、PracticeRecord、Note、Template、Contest、RatingResult…）
- `channels.ts`：IPC 通道名常量
- `ipc-response.ts`：统一响应类型 `{ ok: true, data } | { ok: false, error: { code, message } }`

### 2.3 渲染进程模块（src/renderer/src/）
| 目录 | 内容 |
| ---- | ---- |
| `pages/` | dashboard、problems、stats、notes、templates、contests、rating 七个页面 |
| `components/` | 布局（侧边栏/顶栏）、题库筛选/列表/详情、图表、Markdown 编辑器、代码编辑器、比赛计时器等 |
| `stores/` | Pinia：problems/records/notes/templates/contests/rating/settings |
| `api/` | 对 `window.api` 的类型化封装 |
| `router/` | Vue Router 路由表 |
| `styles/` | 全局样式与主题变量 |

## 3. 进程通信设计（IPC）

### 3.1 通信方式
- 渲染 → 主：`ipcRenderer.invoke(channel, payload)`，主进程 `ipcMain.handle`，**全部走 preload 白名单**。
- 主 → 渲染：同步进度等事件用 `webContents.send(channel, data)`，渲染经 preload 订阅。
- 禁止：渲染进程直接 `require`、`fs`、`net`（contextIsolation + 无 nodeIntegration）。

### 3.2 通道命名规范
`域:动作`，如 `problems:list`、`records:create`。完整清单见 03-详细设计 §3。

### 3.3 统一响应
所有 invoke 返回统一响应包装，渲染侧封装为 `invoke<T>(channel, payload)` 泛型函数，自动解包或抛错。

## 4. 关键技术选型与理由
| 选型 | 理由 |
| ---- | ---- |
| electron-vite | 一体化构建 main/preload/renderer，热更新，模板成熟 |
| better-sqlite3 | 同步 API、性能高、事务简单，适合本地单用户 |
| Pinia | Vue3 官方推荐的轻量状态管理 |
| ECharts | 图表丰富（柱/折线/雷达），文档中文友好 |
| markdown-it + highlight.js | Markdown 渲染与代码高亮，笔记/模板通用 |
| WebContentsView（已废弃） | v1.6 及以前用于内嵌加载 CF/洛谷题面；v1.7 起由独立 BrowserWindow 取代（FR-10） |
| Vitest | 与 Vite 同生态，主进程纯逻辑与 repository 可测 |

## 5. 关键数据流

### 5.1 CF 题库同步
```
Renderer 点击"同步" → api.problems.sync()
  → Main: 请求 CF API（限速 ≥2s，失败重试 1 次）
  → 解析 → 事务写入 problems / tags / problem_tags（upsert）
  → 逐批 send 进度事件 → Renderer 更新进度条
  → 返回 {added, updated, fetchedAt}
```

### 5.2 一次练习闭环
```
题库页选择题目 → 题面独立窗口打开（v1.7）→ 做题 → 在应用内记录结果(AC/WA…)
  → records:create 落库 → 题目标记已练习 → 统计/错题/评估自动更新
```

### 5.3 虚拟比赛
```
创建(组卷: contest.create) → 开始(计时) → 查看题面/记录提交(contest.submit)
  → 结束(contest.finish) → 计算排名/罚时 → 写入 rating_history(比赛分) → 结果页
```

### 5.4 水平评估
```
rating:recalc（手动触发 / 练习与比赛数据变化后触发）
  → 读取练习记录+比赛记录 → 计算 PracticeRating / ContestRating → 综合 Rating
  → 映射称号 → 写入 rating_history → 渲染展示 + 趋势图
```

## 6. 安全设计
1. `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`（preload 仅用有限 API）。
2. 渲染进程仅能调用 preload 暴露的白名单方法。
3. 题面窗口（v1.7 独立 BrowserWindow）开启沙箱并受域名白名单约束，禁止其调用应用能力；外部链接一律在系统浏览器打开。
4. 无任何数据上传；网络请求仅指向 Codeforces API 与题面站点。
5. 渲染进程启用 CSP：仅允许自身资源与 `https://codeforces.com`（题面）相关资源。
