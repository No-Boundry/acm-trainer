# 01 需求规格说明书（SRS）—— ACM-Trainer

- 版本：v1.0（基线）；v1.1–v1.10 的需求以**追加章节**方式记录（FR-8/FR-6.6/FR-9/FR-10/FR-11/FR-17/FR-18，v1.9 的 FR-21 ~ FR-23，v1.9.1 的 FR-24 ~ FR-25，以及 **v1.10 的 FR-26 ~ FR-29**：技能树扩展与国内比赛赛道 / 题单 / 训练计划 / 题单内间隔复习）
- 状态：待评审
- 说明：本说明书定义 ACM-Trainer v1.0 的全部功能与非功能需求，是开发、测试与验收的契约依据；追加章节为后续版本的实际交付需求。

## 1. 引言

### 1.1 目的
为 ACM-Trainer 桌面应用定义明确、可验证的需求规格，作为概要设计（02）、详细设计（03）、测试（04）与任务分解（05）的输入。

### 1.2 读者
项目开发者（本人）、评审者。

### 1.3 术语
| 术语 | 含义 |
| ---- | ---- |
| CF | Codeforces（Codeforces.com） |
| CF Rating | Codeforces 积分体系中的选手分值 |
| 力扣 / LC | 力扣中文站（leetcode.cn）；本文档中 `LC` 亦指该题源与其题目 id 前缀（如 `LC1`） |
| AC | Accepted，通过 |
| WA / TLE / RE / MLE / CE | 错误答案 / 超时 / 运行时错误 / 超内存 / 编译错误 |
| 罚时（Penalty） | ACM 比赛规则中错误提交的惩罚时间，每题 20 分钟 |
| 知识点（Tag） | 题目的算法标签，如 dp、graph、math |
| 题面 | 题目描述正文（Codeforces 网页提供，API 不含） |

## 2. 总体描述

### 2.1 产品定位
面向个人 ACM 训练的一站式本地桌面工具：**题库 → 练习 → 记录 → 复盘（错题/笔记）→ 模板沉淀 → 虚拟比赛 → 水平评估** 的闭环。

### 2.2 用户特征
- 单人使用，计算机专业大二学生；
- 具备基础编程能力，主要使用 C++ 参赛；
- 界面需全中文。

### 2.3 运行环境
- Windows 10/11 桌面应用；
- 联网场景：同步题库、查看题面；
- 离线场景：浏览已缓存题库、查看本地记录/笔记/模板、查看统计（不包含同步与题面）。

### 2.4 需求优先级定义
- **P0**：核心闭环必需，v1.0 必须交付；
- **P1**：重要增强，v1.0 计划交付；
- **P2**：锦上添花，视进度决定。

## 4. 非功能需求（NFR）

| 编号 | 类别 | 需求 |
| ---- | ---- | ---- |
| NFR-1 | 性能 | 冷启动 ≤ 5s；题库列表翻页/筛选响应 ≤ 500ms；统计页渲染 ≤ 1s |
| NFR-2 | 可靠性 | CF 同步失败不影响本地数据；数据库异常自动备份提示；离线可用 |
| NFR-3 | 易用性 | 全中文界面；主要操作 ≤ 3 次点击；键盘可达（Tab/Enter） |
| NFR-4 | 安全 | 渲染进程不直接访问 Node API（contextIsolation）；题面窗口沙箱隔离（v1.7 独立窗口同样沙箱 + 白名单）；无任何账号与网络上传（数据不出本机） |
| NFR-5 | 可维护性 | 分层清晰（main/preload/renderer）；数据库访问集中到 repository 层；关键算法纯函数化可单测 |
| NFR-6 | 兼容性 | Windows 10/11；高分屏（DPI）适配 |
| NFR-7 | 数据一致性 | 记录/笔记/模板修改即时落库；ID 唯一且稳定 |

## 5. 验收标准（概要，详见 04）
1. 全部 P0 功能需求可演示、可操作；
2. 04 测试规范中「手动验收清单」全部勾选通过；
3. 核心算法（水平评估、罚时计算、组卷）通过单元测试；
4. 应用在断网状态下仍可浏览已缓存题库与全部本地功能（题面除外）。

### FR-25 题库排序规则（v1.9.1 新增，P1）

**验收标准（FR-26）**：

### FR-28 训练计划（v1.10 新增，P0，日历排期式）
| 编号 | 需求 | 说明 |
| ---- | ---- | ---- |
| FR-28.1 | 数据模型 | 新表 `training_plans`（name/list_id/target_date/daily_target/rating_min/rating_max/knowledge_ids/rest_weekdays/track_id）+ `plan_tasks`（plan_id/problem_id/due_date/status: `pending`\|`done`\|`skipped`/done_at）+ `plan_busy_days`（plan_id/date/reason） |
| FR-28.2 | 排期规则 | 从**今天**起每个**可用日**排 `dailyTarget` 道题；跳过「每周固定休息日」与「没空日」；给了目标日期则**排到该日期为止**，**超出目标日期的题目计入 overflow 并明确提示**（**不硬塞进最后一天、不静默丢题**） |
| FR-28.3 | 题目来源 | 三种：① 来自**题单**；② **显式题目列表**；③ **「按知识点 + 题量」自动抽题** |

| FR-28.5 | 日历视图 | 按日期分组展示任务，任务可**打卡**（完成/取消）、可看题面 |
| FR-28.6 | 没空日与顺延 | 标记「这天没空」并填原因 → **其后未完成任务自动顺延**（**总题量不变、已完成的不动**）；另有「重新排期」与删除计划 |
| FR-28.7 | 纯函数 | `src/main/services/training-plan.ts`：`scheduleProblems` / `shiftTasks` / `isWorkingDay` / `nextWorkingDay` / `planStats` |

**验收标准（FR-28）**：
1. 选定题单（或自动抽题数量）+ 每日题量后生成计划，日历按日期分组且有待做任务；
2. 任务可打卡，完成态正确渲染，计划列表显示 `完成/总数`；
3. 勾选「每周休息日」或标记「没空日」后，这些日期不出现在排期中（实测：标记 2026-10-06 并填原因「期中考试」后该日期显示原因且任务顺延）；
4. 设置目标日期后，超出的题量以 overflow 提示呈现，**不挤入最后一天**；
5. 「重新排期」保持已完成任务不动、只重排未完成任务；删除计划后其任务与没空日一并清除。
