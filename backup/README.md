# ACM 训练模式(acm-trainer)

一个**本地运行的 ACM/ICPC 风格训练网页应用**:内置题库 + 本地编译判题 + XCPC 训练计划 + 训练统计 + AI 教练。

- 零 npm 依赖,Node.js 直接运行(无需 `npm install`)
- 判题在**本机**编译运行(C11 / C++17 / Python 3),不上传任何代码
- 训练计划来自桌面《2026-XCPC集训练习题.xlsx》,已解析导入为 8 次训练、共 92 道外部 OJ 题
- AI 教练可选接入 DeepSeek 兼容 API;未配置 Key 时自动降级为题目内置提示/题解

## 快速开始

```bash
# 方式一:双击
start.bat

# 方式二:命令行
cd C:\Workspace\acm-trainer
node server.js          # 默认端口 4000,可用 --port 8080 或环境变量 PORT 改端口
```

启动后浏览器打开 **http://127.0.0.1:4000**。

当前服务器已由本会话后台启动,直接访问 http://127.0.0.1:4000 即可。

## 功能

| 模块 | 说明 |
|---|---|
| 题库 | 13 道内置原创题(入门→中等),含题目描述、输入输出格式、样例、分级提示、题解;支持搜索/难度/知识点/**状态**筛选,**按练习情况与导入笔记动态更新**(薄弱题检测、笔记推荐标记、笔记外部题聚合) |
| 在线判题 | 本地编译运行,逐测试点判定 **AC / WA / TLE / MLE / RE / CE / OLE / IE**,返回失败测试点的输入/期望/实际差异,并上报每个测试点的耗时与**峰值内存** |
| 训练计划(题单) | XCPC 2026 暑期集训 8 次训练计划,题目来自洛谷/HDU/POJ,一键跳转原题,可勾选完成并统计进度;洛谷题可显示"洛谷已 AC"状态徽章 |
| 笔记计划 | 导入 .md 笔记(**支持多文件一次导入**),自动解析章节结构、题目引用(洛谷/HDU/POJ)与知识点,每篇笔记生成独立可勾选的学习计划;并按笔记知识点推荐内置题库练习 |
| 洛谷导入 | 把洛谷练习记录(AC 题号列表)导入到训练计划:洛谷题自动显示 AC 状态、一键标记完成、双重进度统计 |
| 统计 | 解题数、提交数、通过率、按难度分布、每题状态、最近提交记录、洛谷已 AC 统计(进度持久化到 `data/progress.json`) |
| AI 教练 | 引导式教学对话,可绑定当前题目上下文;支持 DeepSeek API Key(仅存本机浏览器 localStorage) |

## 笔记导入与学习计划

「笔记计划」页可导入 Markdown 笔记,自动解析并生成学习计划:

- **多文件导入**:文件选择支持一次选中多篇 .md(按住 Ctrl/Shift),每篇笔记生成**独立的学习计划**并保留文件名;也可随时粘贴内容追加为一篇新笔记
- **笔记库管理**:每篇笔记独立展示进度、可单独删除,顶部显示所有笔记汇总的总进度
- **章节任务**:按 `# / ## / ###` 标题切分,每个章节生成一个学习任务(含要点摘要,可折叠展开)
- **题目引用**:自动识别章节内的洛谷(`P1000` / 洛谷P1000 / 完整 URL)、HDU(`hdu1234`)、POJ(`poj1234`)题号,生成带跳转链接的题目 chips
- **知识点推荐**:识别笔记中与内置题库标签重合的知识点(如"动态规划""前缀和""数论"),自动追加一个"推荐练习"任务,直接链接到内置可判题
- **进度追踪**:每个任务可勾选完成,笔记级与总览级进度条;统计页同步展示笔记任务完成数

解析规则:代码块(```)内容跳过;无标题的笔记退化为单一任务;纯题号列表也能识别。

计划数据保存在 `data/progress.json` 的 `notePlans` 字段(旧版单笔记 `notePlan` 会自动迁移)。

## 题库动态更新(基于练习情况与笔记)

题库页会根据你的**练习记录**与**导入的笔记**自动更新,不再只是静态列表:

- **状态筛选**:全部 / 未做 / 尝试中 / 已解决 / 薄弱 / 笔记推荐,可与搜索、难度、知识点组合
- **薄弱题检测**:提交过但未 AC,且非 AC 次数 ≥ 2、通过率 < 50% 的题自动标记 🔥「薄弱」(如 5 次提交 0 AC),统计页有独立的「薄弱题」复习清单
- **笔记推荐**:出现在导入笔记任务/推荐练习里的内置题自动标记 📌「笔记」,可一键筛出
- **笔记外部题聚合**:笔记中引用的洛谷/HDU/POJ 题聚合到题库页底部区块(去重、标注来源笔记),洛谷题若已导入 AC 记录则显示"洛谷已AC"
- 练习情况列直接显示每题的 提交/AC 数与最近判定

## 洛谷练习记录导入

「训练计划」页顶部可导入洛谷练习记录,让题单与你在洛谷上的实际 AC 情况联动:

- **方式一(推荐,离线可用)——粘贴**:在洛谷浏览器里打开 `https://www.luogu.com.cn/user/你的UID?_contentOnly=1`(页面直接显示 JSON),全选复制粘贴到导入框;也可以直接粘贴每行一个题号的列表(如 `P1000`、`洛谷P1029` 均可)
- **方式二(实验性)——UID 在线抓取**:输入洛谷 UID 由服务器抓取;注意本机网络可能无法直连洛谷(中国 CDN),失败时会明确提示改用粘贴

导入后:
- 题单中的洛谷题自动显示 **「洛谷已 AC」/「未 AC」** 徽章(未导入的题不显示)
- 每个训练场次显示 **手动 x/y · 洛谷AC a/b** 双重进度
- 「把洛谷已 AC 的题标记为完成」一键把导入记录同步为手动完成
- 统计页显示洛谷已 AC 总数、计划内覆盖率与题号列表

记录保存在 `data/progress.json` 的 `luogu` 字段,可随时清除重新导入。

## 判题机制

- **语言**:C(gcc -std=c11)、C++(g++ -std=c++17)、Python 3
- **编译**:`-O2` 优化,编译错误(CE)返回完整 g++ 错误信息
- **时间限制**:严格按题目 `timeLimit`(默认 1000ms),超时即终止并判 TLE
- **内存限制**:按题目 `memoryLimit`(默认 256MB)**强制生效**。判题通过 `lib/memlimit.c` 编译出的辅助进程(`lib/.cache/memlimit.exe`,首次运行自动编译,需本机有 g++)每 15ms 采样一次子进程提交内存,超过上限立即强杀并判 **MLE**;退出后还会校验峰值提交内存兜底,并上报每个测试点的峰值内存
  - 说明:Windows 的 Job Object 内存上限只会让 `VirtualAlloc` 失败(程序自行崩溃/处理),不会终止进程,无法稳定判 MLE,因此采用轮询采样方案
  - 辅助进程编译失败时自动降级为"仅时间限制",提交结果会标注 `内存限制未启用`
- **输出比对**:按 ACM 惯例忽略行尾空白与首尾空行(保留内部结构与前导空格)
- **限制**:输出上限 256KB(超限 OLE)、代码上限 256KB
- **并发**:判题队列串行,不会同时跑多个用户程序

> ⚠️ 安全说明:本判题机面向**本地个人训练**,没有进程沙箱隔离(Windows 本地难以低成本实现)。请勿把 4000 端口暴露到公网,也不要运行不信任的代码。

## 目录结构

```

├── server.js              # 零依赖 HTTP 服务器(静态资源 + API)

│   └── progress.json      # 训练进度(运行时生成)
├── public/                # 前端(index.html / css / js)
├── start.bat              # 一键启动
└── README.md
```

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| GET | `/api/problems` | 题目列表(不含隐藏测试) |
| GET | `/api/problems/:id` | 题目详情(不含隐藏测试) |
| POST | `/api/submit` | 提交判题 `{problemId, lang, code}` |
| GET | `/api/xcpc` | XCPC 训练计划 |
| GET | `/api/luogu/user/:uid` | 洛谷 UID 在线抓取(实验性,本机网络需能直连洛谷) |
| GET | `/api/progress` | 读取训练进度 |
| PUT | `/api/progress` | 保存训练进度(整包覆盖) |
| POST | `/api/coach` | AI 教练对话(请求头 `Authorization: Bearer <key>`) |

## 扩展题库

在 `data/problems.js` 中按现有格式追加:

```js
{
  id: 'my-problem',                 // 唯一 id
  title: '题目名',
  source: '原创',
  difficulty: 2,                    // 1~5
  tags: ['动态规划'],
  timeLimit: 1000,                  // ms
  memoryLimit: 256,                 // MB(提示性)
  description: `题目描述…`,
  inputSpec: `输入格式…`,
  outputSpec: `输出格式…`,
  samples: [{ input: '样例输入', output: '样例输出' }],
  tests: [ { input: '隐藏测试输入', output: '期望输出' }, ... ],
  hints: ['提示 1', '提示 2'],
  editorial: `题解…`
}
```

保存后重启服务器即可生效。

## AI 教练配置

「AI 教练」页右上角设置:

- **API Key**:DeepSeek 开放平台申请的 key(https://platform.deepseek.com),仅保存在本机浏览器 localStorage
- **接口地址**:默认 `https://api.deepseek.com/chat/completions`,兼容 OpenAI 格式的服务也可
- **模型**:默认 `deepseek-chat`

教练遵循引导式教学原则:先了解卡点、给分级提示,只有当你明确要求时才给完整解法和代码。

## 已知限制

- 无进程沙箱,仅适合本地个人训练(见上)
- 内存限制为"轮询采样"式强制(15ms 采样间隔),进程可能在采样间隙短暂超出限额;此外内存限制辅助进程依赖本机 g++ 编译
- 判题串行执行,多人同时提交会排队
- 训练计划中的题目是外部 OJ 题,应用内只提供链接与完成度跟踪,无法本地判题
