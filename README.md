面向个人 ACM/ICPC 学习与训练的**本地桌面应用**（Electron 37 + Vue 3 + TypeScript + SQLite）。当前版本 **v1.18.0**，规格驱动开发（SDD），规格文档见 [docs/](docs/)。

- 📚 **题库**：Codeforces（约 1.1 万题）、洛谷 P 题（约 1.6 万题）与**力扣算法题（3930 道）三数据源**（合计 31,764 题），按难度/标签/状态/关键字筛选，**排序规则**（按难度按各题源自己的难度列、按题号数字序、空难度恒排最后、全部视图按题源分组）
- 🧠 **知识点筛选**：**54 个知识点**按 L0–L6 分层展示，带掌握度色点与「已练/已 AC」题数，多选并集筛题（已接入力扣中文标签）；**标签已中英统一（v1.18）**：同一概念的英文标签（`greedy` / `dsu`）在入库时即归并为中文（`贪心` / `并查集`），搜 `greedy` 与搜 `贪心` 等价
- 🎯 **首页推荐习题（v1.14；v1.16 起与题库页共用题源筛选）**：固定「**已练习**」「**未练习**」两栏（默认各 8 条）—— 已练习默认按**遗忘曲线**排序（越久没碰、AC 越少越靠前，紧急度 ≥ 0.5 标「该复习了」），未练习默认**优先「练习中」知识点、组内 AC 数升序**；两栏都支持知识点/标签筛选，点条目直达题库（`?q=<题号>`），条数与排序在设置页「首页推荐习题」面板可调（1–30，改完立刻生效）；**推荐区上方多一行题源切换（全部 / Codeforces / 洛谷 / 力扣），与题库页是同一个状态，在哪边切另一边都跟着变**
- 🏷️ **已练习标签（v1.14）**：每个练过的知识点标签直接显示 **`已AC数/题数`**（如 `greedy 9/9`），未 AC 的标签另列计数，**点 chip 即筛选推荐**；技能树标签按钮同样显示题库题数与 ✅ 已 AC 数，题库无题的标签画虚线
- 🗺️ **学习路径（技能树）**：内置知识图谱（依赖连线、五档掌握度、推荐下一步），一键跳题库练习（**支持单个知识点直达**：卡片「📚」快捷按钮或详情面板按钮）；**v1.14 起关联标签可手动勾选**，只把自己挑的标签带去题库；**5 个国内比赛赛道**（蓝桥杯 / 天梯赛 GPLT / ICPC·CCPC / NOIP·CSP-S / 牛客多校）—— 赛制说明、推荐难度、**必达进度条**、「按赛道去题库练习」
- 📋 **题单**：**三种建法**（题库勾选 / 粘贴题号识别 / 按知识点+难度生成），题单内记录完成状态、备注与复习进度
- 🔁 **题单内间隔复习**：**1 / 3 / 7 / 14 / 30 / 60 天**阶梯，勾选完成自动进入第 1 档；「今日复习」跨题单汇总（逾期也算），反馈 **困难退一档 / 一般进一档 / 轻松跳一档**
- 🗓️ **训练计划**：日历排期式 —— 每日题量、每周休息日、**标记「这天没空」后未完成任务自动顺延**、任务打卡、**超出目标日期的题量明确提示（不硬塞、不丢题）**
- 📝 **练习记录与统计**：结果/耗时/错题标记，ECharts 趋势与知识点分布，**难度分布（按题源）**
- 📓 **笔记与错题本**：Markdown 编辑（代码高亮、Tab 缩进、自动保存）
- 🧩 **模板库**：算法模板分类管理，一键复制
- 📘 **STL 速查**：内置 35 条竞赛 STL 参考资料（容器/算法/复杂度/坑点，**含各容器的初始化与清空写法 + 「初始化与清空速查对照」**，可搜索、一键复制代码、跳转 cppreference）
- ⚔️ **虚拟比赛**：按难度/知识点组卷、限时训练、ACM 罚时计分、结果回看
- 🏅 **水平评估**：综合分（练习+比赛，权重可配）＋ 独立的洛谷练习水平与**力扣练习水平**，历史趋势
- 🔗 **题面**：用 **Edge 浏览器**打开原站页面（CF / 洛谷 / 力扣；v1.8 起不再内嵌网页题面）

## 快速开始

1. 安装：运行 `dist\ACM-Trainer-1.18.0-setup.exe`（或免安装版 `dist\win-unpacked\ACM-Trainer.exe`）；
2. 首次进入「题库」页依次点 **同步题库**（Codeforces，1–3 分钟）、**同步洛谷**（3–5 分钟）、**同步力扣**（约 30–40 秒）；
3. 用「知识点筛选」按知识点练题 → 点「记录」写练习记录（排序可选「按难度 / 按题号 / 按 AC 数」，默认方向自动切换）；
4. 回「🏠 首页」看「**已练习标签**」（chip 显示 `已AC/题数`）与「**推荐习题**」两栏：已练习按遗忘曲线提醒该复习什么，未练习优先推「练习中」知识点的题；点标签 chip 可筛选，点条目直达题库（`?q=<题号>`）；
5. 到「学习路径」看掌握度与推荐，点「去题库练习」一键选中建议知识点，或用卡片右上角「📚」直达**单个知识点**；**打开知识点详情可手动勾选/取消关联标签**，只练自己想练的那几个；也可**切换国内比赛赛道**看必达进度；
6. 到「📋 题单/计划」把要练的题组成题单（题库勾选 / 粘贴题号 / 按知识点生成），用「🔁 今日复习」按间隔复习；
7. 到「🗓️ 训练计划」按每日题量排上日历，标记没空日自动顺延，做完就地打卡；
8. 到「⚙️ 设置 → 首页推荐习题」调两栏的**排序方式**与**条数（1–30）**，回首页立即生效；
9. 到「统计 → 难度分布（按题源）」看各难度段的已练/AC 情况。

## 环境备注（Windows）

- npm.ps1 被执行策略禁止时使用 `npm.cmd`；
- npm 11 首次安装需 `npm install-scripts approve better-sqlite3 electron esbuild vue-demi`；
- SQLite 使用 better-sqlite3 v13（Node-API 预编译，无需本机 C++ 工具链）；
- 题面统一由 **Edge 浏览器**打开；未检测到 Edge 时回退系统默认浏览器；
- GUI 自动化脚本启动时会剔除环境变量 `ELECTRON_RUN_AS_NODE`（该变量会让 electron.exe 退化为纯 Node，无法创建窗口）。

## 版本说明

### v1.18.0
本版把**同一概念的中英文标签统一成一个标签**：CF 题的 `greedy` 与洛谷/力扣题的 `贪心` 现在入库时就归并为 `贪心`（`dsu` → `并查集`、`dp` → `动态规划`…）。**无新增数据表、无新增 IPC 通道、无新增设置项、无新字段**，覆盖安装即可（旧库首次启动自动迁移一次，幂等）。

- **之前的现象**：`tags` 表以标签名为唯一键，英文标签与中文标签就是两行 → 同一概念被劈成两半。真实库实测 `dsu + 并查集` **交集 0 → 并集 907**、`greedy + 贪心` 交集 **0** → 并集 **5752**（交集为 0 = 两批题完全不重叠）。后果：① 按 `greedy` 筛与按 `贪心` 筛得到**不相交**的两批题；② 点技能树「并查集」节点（`tags: ['dsu', '并查集']`）时同一道题被算成「命中 2 个不同标签」，v1.17 的命中数排序与 `命中 N/M` 角标虚高；③ 首页「已练习标签」里同一概念两个 chip 各带一半题数。
- **映射表**：新增 `src/shared/tag-map.ts` —— `TAG_ALIASES`（canonical → 别名数组，**53 canonical + 71 别名 = 124 名称**）、`canonicalTag(name)`（大小写与多余空白不敏感，未收录原样返回）、`canonicalTags(names)`（canonical 化 + 去重 + 保序 + 过滤空串）。**canonical 取中文**：UI 全中文，且中文标签覆盖面大得多（洛谷 452 + 力扣 171 vs CF 122）。
- **写入即物化**：`upsertMany()` 的标签写入改为 `for (const tagName of canonicalTags(p.tags))`，**一处改动同时覆盖 CF / 洛谷 / 力扣三条写入路径**；一题同时带 `greedy` 与 `贪心` 时去重，库里只留 `贪心`。**不在查询期展开别名** —— 命中数排序是 `COUNT(DISTINCT t.id)`（按标签行计数）、`tagUsage` 是 `GROUP BY t.id`（按行分组），查询期展开会把同一概念算成 2 个命中，排序与角标一起错。
- **查询与统计同步归一**：`buildWhere()`（`tags` / `tagsAny`）、`matchedTagsOrderPrefix()`、`idsForKnowledge()`、`tagUsage()` 全部先 `canonicalTags()` 再拼 `@tagN` / `@anyTagN`；`skill.ts` 的 `nodeTagSet` 与记录侧 tags 都过 `canonicalTags(...).map(lower)`，技能报告输出 `tags: canonicalTags(n.tags)`（渲染层不用改）；`tag-categories.ts` 的 `categorizeTag()` 先 canonicalize 再归类、归不到退回原名（保留英文条目兼容）。
- **旧库迁移**：新增 `migrateProblemTagsToCanonical(db): number`，在 `migrate()` 末尾执行 —— 找别名行 → 事务内 `INSERT OR IGNORE` 建 canonical 行 → `INSERT OR IGNORE … SELECT` 搬题目关联 → 删旧关联 → 删别名行（先判 `target.id === row.id`）；**幂等**（第二次返回 0）。本机真实库标签 **574 → 516**（净 −58 = 合并 70 个别名行 − 新增 12 个此前不存在的 canonical 行）、`problem_tags` 关联 **113664 → 113577**（同题中英双写去重 87 条）、迁移后 0 个无题标签；题量与练习记录一条不少。
- **不映射的标签**：来源/赛事类（`Special Judge`、`ICPC`、`USACO`、`洛谷原创`、各省省选、年份）与 `Ad-hoc`、`STL`、`Tarjan`、`K-D Tree` 原样保留 —— 它们不是同一概念的另一种拼写。

测试 **515/515（46 文件）**、`verify:gui` **112/112**（新增 2 项）、`verify:smoke` **33/33**、`tsc` + `vue-tsc` **0 错误**；本版不新增截图。
对应需求 **FR-38**（[docs/01-需求规格说明书.md](docs/01-需求规格说明书.md)）、设计 [docs/03-详细设计.md](docs/03-详细设计.md) §29。
详见 [docs/08-发布说明.md](docs/08-发布说明.md) §24。

### v1.17.0
本版把题库页的**标签筛选从交集改为并集**，并按**命中标签数降序**排序（命中越多越靠前，命中数相同再按你选的排序方式）。**无新增数据表、无新增 IPC 通道、无新增设置项**，覆盖安装即可。

- **之前的现象**：标签是交集语义（题目必须同时带全部已选标签）。技能树里有些知识点节点关联多个标签（如「贪心」挂 `greedy` + `贪心`），点一个节点就等于同时勾上多个标签，常直接筛出 **0 题** —— 与「点节点 = 勾选它关联的全部标签」的预期相反。
- **并集语义**：`buildWhere()` 的 `filter.tags` 分支由 `GROUP BY pt.problem_id HAVING COUNT(DISTINCT t.id) = <已选标签数>` 改为子查询并集 `p.id IN (SELECT pt.problem_id FROM problem_tags pt JOIN tags t ON t.id = pt.tag_id WHERE t.name IN (@tag0, …))`；未知标签在并集下被忽略，不再把列表清空。
- **排序**：新增私有函数 `matchedTagsOrderPrefix(tags?: string[])`，未选标签时返回**空串**（ORDER BY 与旧版逐字符一致），有标签时返回命中数子查询作为 ORDER BY 前缀，拼到 `buildOrderSql()` 的 4 个 return 分支最前。它复用 `buildWhere()` 注册的 `@tagN`，因此**必须先 `buildWhere()` 再拼 ORDER BY**。
- **界面**：命中数可见化 —— 已选标签 ≥ 2 个时，题目行标签区末尾显示琥珀色 `命中 N/M` 角标（`N` 命中数 / `M` 已选数），「已选」条提示「取并集 · 命中标签越多越靠前」；只选 1 个标签时两者都不出现。
- **未动**：题单自动抽题用的 `filter.tagsAny` 本来就是并集，本版未改动；`problem_tags` 表结构与数据不变，**无数据迁移**。

测试 **487/487（44 文件）**、`verify:gui` **110/110**（新增 5 项）、`verify:smoke` **33/33**、`tsc` + `vue-tsc` **0 错误**。
详见 [docs/08-发布说明.md](docs/08-发布说明.md) §23。

### v1.16.0
本版把首页「推荐习题」与题库页的**题源（平台）筛选**合并成同一个状态：在哪边切题源，另一边都跟着变。**无新增数据表、无新增 IPC 通道、无新增设置项**，覆盖安装即可。

- **之前的现象**：首页推荐永远按「全部平台」推荐。用户在题库页选了「洛谷」，回首页看到的仍是三源混合的结果，两页口径不一致。
- **状态源**：沿用 Pinia `problems` store 里已有的 `filter.source`（`'all' | 'cf' | 'luogu' | 'leetcode'`）作为**全局唯一题源状态**。`App.vue` 的 `<RouterView />` 没有 keep-alive、切页会重新挂载，读写同一个 store 就自然联动，因此**没有引入事件总线，也没有把题源存到后端**。
- **界面**：推荐区上方新增一行题源按钮（全部 / Codeforces / 洛谷 / 力扣），右侧文案「与题库页同步：当前推荐全部平台」／「当前只推荐 洛谷」；非「全部」时推荐面板标题旁标注「仅 洛谷」、「已练习标签」标题追加「（仅 洛谷）」、未练习空态文案改为「洛谷中没有符合条件的未练习题目」。
- **请求链路**：`recommend:get` 与 `stats:tagUsage` 各加一个 `source` 参数（**复用已有通道，仅扩展参数**）；`ProblemsRepo.tagUsage(tagFilter?, source)` 把题源条件和标签条件用 `AND` 拼进同一条 SQL；`practicedTags()` 透传 `source` 并把它并入缓存键，避免「切到洛谷后仍看到全平台计数」；`source` 在 `mergeRecommendSettings()` 里归一化，只接受 `cf/luogu/leetcode`，非法值退化为 `all`，防止脏值把推荐静默清空。
- **顺带小修**：`ProblemsStore.setSource()` 改为 `void this.setFilter(next).catch(() => undefined)`，不再因模板直接调用 action 抛出未处理的 Promise 拒绝。

### v1.14.1

**v1.14.1 是性能补丁版**：只修性能，**无新功能、无新增数据表、无新增 IPC 通道、无新增设置项**，覆盖安装即可。
修的是用户反馈的「**首页跳转题库有明显卡顿**」+「**启动速度明显变慢**」——两者同一根因：首页推荐要取整个题库，
旧实现用分页接口一页页翻（3 万题要翻 **159 页**，每行还带标签聚合 / `EXISTS` 已练习 / 最近状态 **3 个相关子查询**），
真实库（31764 题）实测 **9072 ms**，而精简列单条 SQL 只要 **83 ms**（109 倍）；更关键的是本地库是**同步** API 且跑在主进程，
这 9 秒会把所有页面切换与 IPC 一起堵住，所以用户看到的是「启动慢 + 跳题库卡」。
修复：新增 `ProblemsRepo.leanAll()`（单条精简 SQL 取全库）+ 三级缓存（题库 / 标签统计 / 推荐结果，数据一变缓存键就变、随机排序不缓存）+ 首页 `requestAnimationFrame` 先出统计卡片；
顺带修掉 `RecordsRepo.list()` 的 **200 条静默截断**（技能掌握度 / 水平评估 / 首页已练习段 / 组卷候选 4 处调用点改用新增的 `records.all()`）。
实测：首页统计卡片 **13984 → 787 ms**、`recommend:get` **12498 → 33 ms**、题库→首页 **12802 → 157 ms**；
新增 `npm run verify:perf` 性能自查（复制真实库副本测量，不写真实数据）。测试 **458/458（43 文件）**。
